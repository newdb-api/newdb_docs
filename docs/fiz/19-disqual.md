# disqual — Реестр дисквалифицированных лиц

POST `https://api.newdb.net/v2`

Метод получает сведения из [открытого реестра ФНС](https://service.nalog.ru/disqualified.do) онлайн при выполнении запроса. Поиск выполняется через браузер с перехватом JSON-ответа ФНС. Метод полезен для проверки кандидатов на руководящие должности и руководителей контрагентов.

Все ФИО, даты, номера записей, организации и места в примерах вымышлены. Примеры показывают формат ответа и не являются сведениями о реальных лицах.

## Запрос

```http
Content-Type: application/json
X-API-KEY: <your_token>
```

```json
{
  "params": {
    "method": "disqual",
    "query": "Примеров Тест Тестович"
  },
  "requestId": "00000000-0000-4000-8000-000000000019"
}
```

Для уточнения результата можно дополнительно передать `"dob": "12.02.1980"`.

| Параметр в `params` | Обязательный | Описание |
|---|---|---|
| `method` | Да | `disqual` |
| `query` | Да | Непустая поисковая строка, до 1000 символов. ФИО, название или ИНН организации — строка передаётся в поиск ФНС. |
| `dob` | Нет | Дата рождения: `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`. Дополнительный фильтр полученных записей, а не параметр поиска ФНС. |
| `max_pages` | Нет | Максимальное количество страниц ФНС: от 1 до 100, по умолчанию 20. |

Используйте `query` в публичных API-запросах: он обязателен в зарегистрированной схеме метода. Внутри spider также поддерживаются `fio` и составление ФИО из `lastname`, `firstname`, `secondname`, но они не заменяют обязательный `query` в публичной схеме.

Ниже — содержимое `results.disqual.result`, а не транспортная оболочка всего API-ответа.

```json
      "birth_date": "12.02.1980",
      "birth_place": "Г. ПРИМЕРНЫЙ",
      "organization": "ООО УЧЕБНЫЙ ПРИМЕР",
      "position": "РУКОВОДИТЕЛЬ",
      "offence": "ПРИМЕР КВАЛИФИКАЦИИ ПРАВОНАРУШЕНИЯ",
      "protocol_authority": "ТЕСТОВЫЙ ОРГАН",
      "judge_name": "ОБРАЗЦОВА ТЕСТА ПРИМЕРОВНА",
      "judge_position": "СУДЬЯ",
      "duration": "0 г 6 м 0 д",
      "start_date": "01.01.2026",
      "end_date": "30.06.2026",
      "source_updated_at": "01.07.2026 12:00:00",
      "source_url": "https://service.nalog.ru/disqualified.do"
    }
  ],
  "found": true,
  "registry_status": "found",
  "meta": {
    "query": "Примеров Тест Тестович",
    "dob": null,
    "row_count": 1,
    "page_count": 1,
    "pages_fetched": 1,
    "count": 1,
    "complete": true,
    "source_url": "https://service.nalog.ru/disqualified.do",
    "identity_match": "query_only"
  }
}
```

!!! note "Формат дат"
    В примере показан подготовленный формат `birth_date`, `start_date`, `end_date` без времени. В ранее опубликованной версии spider эти поля содержат время, например `12.02.1980 00:00:00`. До обновления рабочих серверов интеграция должна принимать оба варианта. `source_updated_at` сохраняет время обновления источника.

## Поля записи

| Поле | Значение |
|---|---|
| `record_number` | Номер записи в реестре |
| `full_name`, `birth_date`, `birth_place` | ФИО, дата и место рождения |
| `organization`, `position` | Организация и должность из записи ФНС |
| `offence` | Квалификация правонарушения |
| `protocol_authority` | Орган, составивший протокол |
| `judge_name`, `judge_position` | ФИО и должность судьи |
| `duration` | Срок дисквалификации, текст источника |
| `start_date`, `end_date` | Начало и окончание дисквалификации |
| `source_updated_at` | Дата формирования сведений источника, не время API-запроса |
| `source_url` | Страница реестра ФНС |

Отсутствующие поля источника могут возвращаться как `null` или пустая строка.

## Совпадения и полнота

- Без `dob` возвращаются все записи, найденные ФНС по строке поиска. При переданном `dob` применяется точное сравнение даты рождения.
- `meta.row_count` — общее число записей ФНС до фильтра по дате рождения; `meta.count` — число возвращённых записей после фильтра.
- `meta.page_count` — количество страниц ФНС; `meta.pages_fetched` — число прочитанных страниц; `meta.complete` — прочитаны ли все страницы.
- При превышении `max_pages` возвращается собранная часть с `complete: false`. Увеличьте лимит или уточните запрос. Это не пользовательская пагинация с курсором: новый запрос начинает чтение сначала.
- `identity_match` равен `query_only` либо `query_and_birth_date`. Это описание критериев поиска, не гарантия идентификации человека.

## Статусы

| Ситуация | `status` | `found` | `registry_status` | `data` |
|---|---|---|---|---|
| Есть совпадения | 200 | `true` | `found` | Записи; проверяйте `meta.complete` |
| Полный поиск без совпадений | 200 | `false` | `not_found` | `[]` |
| Неполный поиск без совпадений | 200 | `null` | `incomplete` | `[]` |
| Ошибка входных параметров | 400 | Не передаётся | Не передаётся | `[]`, описание в `error` |
| Сбой сайта, CDP, капча или некорректный ответ ФНС | 500 | Не передаётся | Не передаётся | `[]`, `error: "wait retry"` |

Капча и техническая ошибка не означают отсутствие лица в реестре. На уровне служебной оболочки spider системный сбой имеет `status: "error"`; завершённый поиск — `status: "success"`.

Наличие записи не является автоматическим заключением о действующей дисквалификации: проверяйте личность, даты и содержание записи. Метод не формирует отдельный признак действующей дисквалификации.
