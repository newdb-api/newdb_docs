# act_text_search — поиск судебных актов по тексту

POST `https://api.newdb.net/v2` с заголовками `Content-Type: application/json` и `X-API-KEY: <your_token>`.

Метод ищет фрагмент текста в судебных актах ГАС Правосудие. В обычном текстовом режиме каждый элемент `result.data` — **один совпавший акт**, дополненный полями дела и участниками. В ответе не более **20 актов**, включая несколько актов одного дела. Для полной карточки дела используйте [pravo_cases_details](01-pravo_cases_details.md).

## Параметры

| Параметр | Описание |
|---|---|
| `method` | `act_text_search` |
| `country` | `ru` |
| `act_text` | Обязательный непустой фрагмент текста. Поиск регистрозависимый, через `LIKE '%фрагмент%'`; `%` и `_` сохраняют смысл шаблонов SQL LIKE. |
| `page_size` | От 1 до 20, по умолчанию 20. Большее значение ограничивается до 20. Алиасы: `pageSize`, `limit`. |
| `cursor` | Строка из `meta.next_cursor` предыдущего ответа. В первом запросе отсутствует. Нельзя менять поисковый текст и фильтры при продолжении. |
| `page` | Для первого запроса допускается только `1`. Переход через `page=2` и далее заменён курсором. |

Дополнительные фильтры дела (`case_number`, `court_url`, `judge_name` и другие фильтры [pravo_search](02-pravo_search.md)) сохраняются.

## Первая страница

```json
{
  "params": {
    "method": "act_text_search",
    "country": "ru",
    "act_text": "пример текста судебного акта",
    "page_size": 20
  }
}
```

API работает асинхронно: дождитесь `state=complete` по полученному `requestId`.

## Продолжение поиска

Скопируйте `results.act_text_search.result.meta.next_cursor` в `params.cursor` нового запроса. Сохраните поисковые параметры. Для следующей страницы создайте новый запрос с новым `requestId` или без него; повторный опрос старого `requestId` возвращает прежнюю страницу.

```json
{
  "params": {
    "method": "act_text_search",
    "country": "ru",
    "act_text": "пример текста судебного акта",
    "page_size": 20,
    "cursor": "<meta.next_cursor из предыдущего ответа>"
  }
}
```

Акты выдаются по убыванию `act_id`. Курсор сохраняет место просмотра. Добавленные после начала поиска акты с большими ID не попадают в продолжение; для свежего поиска начните без курсора. Это не снимок БД: изменения текстов существующих актов между запросами могут влиять на результаты.

### Неполная страница

Объём просмотра за один запрос ограничен по времени. При редких совпадениях ответ может содержать **меньше 20 актов или пустой `data`**, но иметь `has_more=true` и `scan_incomplete=true`. Это означает, что поиск ещё не просмотрел оставшиеся акты. Продолжайте по `next_cursor`, даже после пустой страницы. `has_more` означает наличие продолжения просмотра, а не гарантию следующего совпадения.

Поиск закончен только при `has_more=false` и `next_cursor=null`. Полное число совпадений и страниц не подсчитывается: `total_count` и `pages_count` равны `null`. `count` и `returned_count` — количество актов именно в текущем ответе.

## Пример результата

```json
{
  "state": "complete",
  "results": {
    "act_text_search": {
      "result": {
        "status": 200,
        "data": [
          {
            "act_id": 987654,
            "case_id": 123456,
            "case_number": "1-1/2026",
            "act_title": "Решение",
            "act_text": "Пример текста судебного акта.",
            "parties": [],
            "acts": [
              {
                "act_id": 987654,
                "case_id": 123456,
                "act_title": "Решение",
                "act_text": "Пример текста судебного акта."
              }
            ]
          }
        ],
        "meta": {
          "pagination": "cursor",
          "result_unit": "act",
          "page_size": 20,
          "returned_count": 1,
          "count": 1,
          "total_count": null,
          "pages_count": null,
          "has_more": false,
          "next_cursor": null,
          "scan_incomplete": false,
          "scanned_acts": 1000
        }
      }
    }
  }
}
```

Поле `acts` содержит только совпавший акт текущего элемента, а не все акты дела. Поля `act_id`, `act_title`, `act_text`, `case_id` доступны непосредственно в элементе `data`.

Некорректный курсор, изменённые фильтры или `page>1` без курсора возвращают `error=validation_error`, описание в `message` и пустой `data`. Новая пагинация применяется к обычному текстовому поиску и включается при любом непустом `act_text`, независимо от значения `method` (например, `ods_case_search` с `act_text`); явно выбранный `search_mode=semantic` сохраняет прежний режим поиска и пагинации дел.

## Изменение контракта — 14 октября 2026

Обычный поиск возвращает акты вместо сгруппированных дел. Переход по номеру страницы заменён курсором, точные итоги не подсчитываются. Интеграции должны читать `act_id`, `next_cursor` и `has_more`, а не вычислять число страниц через `total_count`.
